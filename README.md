# 短信通知

把手机上的短信，变成 Windows 桌面上的通知。验证码可以在通知上直接复制。

请只在安全的家庭网络或可信局域网里使用。校园网、公司局域网、公共网络和不可信网络都不适合。如果还不了解局域网，请先不要使用。

需要 Windows 10 或 Windows 11，以及一台安装了 [SmsForwarder](https://github.com/pppscn/SmsForwarder) 的 Android 手机。手机和电脑要在同一个局域网里。

## 它怎么工作

手机上的 SmsForwarder 把短信通过 Webhook 发到电脑。电脑上的后台服务收到后，弹出 Windows 通知。通知上提供「复制验证码」和「复制内容」两个按钮。

## 第一次使用

1. 双击 `启动.bat`。
2. 第一次运行会自动生成密钥，并启动电脑上的服务。默认不记录日志。窗口会显示：
   - 电脑 IP 地址
   - Webhook 地址
   - 密钥
   - `Authorization: Bearer ...`
3. 第一次安装开机自启时，Windows 会弹出管理员授权，请选择允许。
4. 窗口会同时打开本页面。按下面的步骤配置手机。

如果窗口提示没有检测到局域网地址，请先连接 Wi-Fi 或网线，再重新双击 `启动.bat`。

## 在手机上配置 SmsForwarder

### 1. 安装 SmsForwarder

在 Android 手机上安装 [SmsForwarder](https://github.com/pppscn/SmsForwarder/releases)，并允许短信和通知权限。

### 2. 新建发送通道

1. 打开 SmsForwarder。
2. 点击下方栏的「发送通道」。
3. 点击屏幕左上角的「+」号。
4. 选择「webhook」。
5. 随意填写一个「通道名称」。

### 3. 填写 Webhook 地址

在「webhook server」中填写启动窗口给出的地址：

```text
http://<电脑IP>:17890/webhook
```

例如：

```text
http://192.168.1.23:17890/webhook
```

不要填 `127.0.0.1`。手机访问不到电脑的 `127.0.0.1`。

### 4. 添加请求头

1. 滑动屏幕到下方「Headers」。
2. 点击「Headers」旁边的「+」号。
3. Key 填写：

```text
Authorization
```

4. Value 填写启动窗口给出的整段文字：

```text
Bearer <密钥>
```

`Bearer` 后面有一个空格，空格后面是密钥。

### 5. 填写消息模板

在消息模板中填入下面这一行：

```json
{"appName":"{{APP_NAME}}","title":"{{TITLE}}","body":"{{MSG}}"}
```

这是最小可用模板。先确认能收到通知，再按需要增加字段。

### 6. 测试

点击手机屏幕右下角绿色的测试按钮。电脑屏幕右侧应出现通知。

如果手机显示测试失败，先检查第 4 步的 Header：

- Key 必须是 `Authorization`。
- Value 必须是 `Bearer`、一个空格、再加密钥。
- Value 前后不要有多余的空格或换行。

### 7. 新建转发规则

1. 点击屏幕下方的「转发规则」。
2. 点击右上角的「+」号。
3. 选择刚才创建的发送通道。
4. 选择对应的卡槽。
5. 点击右下角的「测试」。

电脑收到通知后，再用手机给自己发一条真实短信，确认短信内容也能收到，并且通知上的「复制验证码」按钮可用。

## 以后查看密钥和 IP

再双击 `启动.bat`。窗口会显示电脑 IP 和服务状态，并提供下面的菜单：

- 显示密钥
- 重新生成密钥
- 电脑 IP 地址查看
- 日志记录：关闭 / 开启
- 打开使用教程
- 退出

用键盘的 `↑`、`↓` 移动，`Enter` 确认，`Esc` 退出。退出菜单后，服务会继续在后台运行。

### 显示密钥

显示完整的密钥，以及手机端应该填写的 `Authorization: Bearer ...`。

### 重新生成密钥

重新生成后，旧密钥立即失效。窗口会选择是否继续，默认是「否」。选择「是」后：

1. 生成新密钥并保存。
2. 如果服务正在运行，自动重启服务。
3. 显示新的密钥和 `Authorization`。

之后必须到 SmsForwarder 的发送通道里，把 Headers 中的 `Authorization` 改成新的值，否则手机会收到 401。

### 电脑 IP 地址查看

列出电脑当前可用的局域网地址和对应的 Webhook 地址。带「推荐」标记的是优先使用的地址。

手机要填的是与电脑同一个 Wi-Fi 的那个地址。如果电脑有多块网卡，不要选 VMware、Hyper-V 之类的虚拟网卡。

### 日志记录

默认不记录日志，也不会创建 `logs` 文件夹。

在菜单中选择「日志记录」一项可以切换开关，服务会自动重启。开启后，日志写入 `logs\server.log`：

- 记录启动、停止、连接来源、请求结果和错误。
- 可能包含短信标题和 App 名称，不记录短信正文。
- 日志超过 2 MB 时会轮换为 `server.log.old`。

关闭日志不会删除已有日志。需要清理时，手动删除 `logs` 文件夹。

## 固定电脑 IP

不固定也能用。只要电脑 IP 不变，手机里的地址就一直有效。

如果路由器重新分配了 IP，手机会连不上电脑。可以二选一：

- 在路由器里找到 DHCP 静态分配或地址保留，把电脑的 MAC 地址绑定到当前 IP。
- 在 Windows 的网络设置里，把当前地址设为静态 IP。

改完 IP 后，用「电脑 IP 地址查看」确认新地址，并更新手机里的 Webhook 地址。

## 遇到问题

**手机显示测试失败，电脑没有通知**

回到 SmsForwarder 的发送通道，确认已经点过 Headers 旁边的「+」。Key 是 `Authorization`，Value 必须是 `Bearer`、一个空格、再加密钥，和启动窗口里的整段文字一致。改完后再点绿色测试按钮。

**手机一直连不上电脑**

确认手机和电脑在同一个网络。地址要使用启动窗口给出的局域网地址，不要填 `127.0.0.1`。`198.18` 或 `169.254` 开头的地址手机也访问不到。

**电脑没有弹出通知**

打开 Windows 的「设置 → 系统 → 通知」，确认允许通知。专注助手或勿扰模式打开时，通知可能被挡住。

**提示端口被占用**

打开 `config.json`，把 `port` 改成另一个端口，再双击一次 `启动.bat`。手机里的 Webhook 地址也要改成新端口。

**服务没有运行**

默认不记录日志。在菜单中选择「日志记录：开启」，再复现问题，然后查看 `logs\server.log`。常见原因是端口被占用，或者防火墙/URL 保留没有安装成功。如果日志提示端口被占用，修改 `config.json` 的 `port` 后重新启动。

**重新生成密钥后手机一直 401**

手机里的 Header 还是旧密钥。回到发送通道，把 `Authorization` 改成新的 `Bearer ...`。

## 安全

- Webhook 使用 HTTP，短信内容在局域网内明文传输。只在可信局域网使用。
- 密钥保存在 `config.json`。不要把 `config.json` 上传到公开仓库或发给别人。
- 开启日志后，日志可能包含短信标题和 App 名称，不记录短信正文。排查完成后可以关闭日志。
- 如果这个项目的仓库是公开的，请确认 `config.json` 没有被提交。需要时用「重新生成密钥」换掉已经暴露的密钥。

## 卸载

双击 `卸载.bat`，并允许管理员授权。它会去掉开机自启、防火墙规则、URL 保留和正在运行的服务。

不要直接删除整个文件夹。服务在后台运行时，文件夹可能被进程占用；直接删除还会留下计划任务、防火墙规则、URL 保留、开始菜单快捷方式和 `smsnotifier:` 协议。先卸载，再删除文件夹。

`卸载.bat` 不会删除 `config.json`、`logs` 和 `data`。确认不再使用后，可以手动删除整个文件夹。

## 文件说明

- `启动.bat`：启动服务并打开管理菜单。
- `卸载.bat`：卸载开机自启、防火墙规则和服务。
- `config.json`：端口、Webhook 路径、密钥。
- `config.example.json`：配置示例。首次启动会自动生成 `config.json`。
- `start.ps1`：启动、菜单和配置逻辑。
- `server.ps1`：接收 Webhook 并弹出通知。
- `start.vbs`：在后台启动 `server.ps1`。
- `logs\server.log`：运行日志。默认不生成，在菜单开启日志后出现。
- `data\`：通知复制按钮使用的临时内容。
